# データセットについて（F-DATA）

## 出典

- 名称: F-DATA (A Fugaku Workload Dataset for Job-centric Predictive Modelling in HPC Systems)
- 著者: Francesco Antici et al.
- 掲載誌: *Scientific Data* (2025)
- データ公開場所: Zenodo, DOI [10.5281/zenodo.11467483](https://doi.org/10.5281/zenodo.11467483)
- 参考リポジトリ（特徴量一覧・前処理スクリプト）: https://github.com/francescoantici/F-DATA

## 内容

スーパーコンピュータ「富岳」における2021年3月〜2024年4月のジョブ実行ログ。
約2400万件、45特徴量、月ごとのparquetファイル（全38ファイル、合計約28GB）に
分割されている。

本プロジェクトでは、このうち2021年3月を除く37ファイルを使用する
（`src/config.py` の `TRAIN_FILES` / `VAL_FILES` / `TEST_FILES`）。
2021年3月はFugaku運用開始直後の月であり、日別のジョブ投入件数を確認すると
1桁〜数百件しかない閑散日が10日ほど含まれる（4月以降は最も少ない日でも
700件以上と安定している）ため、通常の利用実態を表さない期間として
除外している。

| 用途 | 期間 | ファイル数 |
|---|---|---|
| 学習(train) | 2021年4月 〜 2023年12月 | 33 |
| 検証(val) | 2024年1月・2月 | 2 |
| テスト(test) | 2024年3月・4月 | 2 |

学習・検証・テストは時系列順に完全に分離されており、検証・テストは
学習期間より必ず未来のデータになっている。

## 実データで確認した主な特徴（EDA）

- ターゲット変数 `exit state` は `completed`（成功） / `failed`（失敗）の
  2値で、成功が多数派のクラス不均衡なデータである。ただし成功率は
  年や月によって変動があり（データセット全体で概ね80〜95%程度の範囲で
  推移する）、単一の月だけを見て評価すると実態と乖離するリスクがある。
- `ec`（終了コード）は `exit state == completed` のとき常に `0`、
  `failed` のときは複数の値を取る。本アプリでは二値分類のターゲットとして
  `exit state` をそのまま使用している。
- `jobenv_req`（ジョブ実行環境、キュー／リソースグループに相当、匿名化
  済み）は、2021年4月〜2024年3月の約3年間はほぼ100%が同一カテゴリで
  占められているのに対し、2024年4月だけ突然ほぼ全てが別カテゴリに
  切り替わる。周期的な季節変動ではなく、運用体制か資源配分の枠組みが
  一度きり変わったことを示す変数だと考えられ、将来の期間に汎化しないため
  特徴量には使用していない（詳細は [`feature_leakage.md`](feature_leakage.md)）。
- `nnumr`（要求ノード数）は裾の重い分布で、中央値は数ノード程度だが
  最大で15万ノード超の要求も存在する。
- `mszl`（要求メモリ上限）は多くのジョブで「上限なし」を表すセンチネル
  値（2^64-1）になっているが、明示的に値を指定するジョブも一定数存在し、
  指定時の値は1〜28.5GiB程度に収まる。
- `usr`（投入ユーザー）は匿名化されたIDであり、実際の富岳のユーザー名には
  対応しない。月をまたいでも同一の匿名化IDが同一人物を指すことは確認して
  いるが、外部の利用者が実名で入力しても一致しないため、本アプリの
  特徴量・UIには含めていない（詳細は [`feature_leakage.md`](feature_leakage.md)）。

これらの確認結果に基づいて特徴量を設計した経緯は
[`feature_leakage.md`](feature_leakage.md) にまとめている。
