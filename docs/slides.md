# 冨岳ジョブ成功率予測Webアプリ

ジョブを投入する前に、成功確率をニューラルネットワークで予測する

## 【2】目的

- スーパーコンピュータ「冨岳」では、ジョブが**失敗して終了**すると、
  確保していた計算資源・時間がそのまま無駄になってしまう
- 「投入する前に、この設定で成功しそうかどうか分かれば」という発想からスタート
- ノード数・実行時間・メモリ上限などの**投入条件だけ**から、
  そのジョブが成功するかをその場で予測するツールを作った
- 学習・開発を通じて「データリークを防ぎながら、実際に投入前に
  使える予測モデルを作る」という機械学習エンジニアリングの練習も兼ねている

---

## 【3】技術説明 ①: 使用データ

- **F-DATA**（Antici et al., *Scientific Data*, 2025）
  - 冨岳の実ジョブ実行ログ、Zenodoで公開（CC BY 4.0）
  - 2021年〜2024年、約2500万件のジョブ、45種類の特徴量
- 今回はこのうち**約37ヶ月分・約2500万件**を学習に使用
- ターゲット: ジョブの終了状態（`completed`=成功 / `failed`=失敗）の二値分類

---

## 【3】技術説明 ②: ニューラルネットワークの仕組み

今回使ったのは **多層パーセプトロン（MLP）** というシンプルな構造

```
入力層          隠れ層1        隠れ層2        出力層
(特徴量8個) → (64ユニット) → (32ユニット) → (1ユニット)
                 + ReLU         + ReLU        + シグモイド
                                                   ↓
                                            成功確率 (0〜1)
```

- 各層は「入力を重み付けして足し合わせ、活性化関数を通す」を繰り返すだけ
- 学習では、正解（成功/失敗）と予測のズレ（損失）を計算し、
  誤差逆伝播法でネットワーク内の重みを少しずつ調整する
- これを大量のジョブデータで繰り返すことで、
  「こういう条件のジョブは成功しやすい／失敗しやすい」というパターンを学習する

---

## 【3】技術説明 ③: 学習・予測の工夫

- **クラス不均衡への対応**: 失敗ジョブは少数派なので、失敗クラスの損失を
  重み付けして学習（`sklearn`の`balanced`と同じ考え方）
- **確率較正（Platt scaling）**: 上の重み付けだけだと出力確率が歪むため、
  検証データで較正し直し、「成功確率○%」が実際の成功率に近づくよう補正
- **時系列を考慮した検証**: 学習・検証・テストを時系列で完全に分離し、
  「未来のデータに対してどれだけ予測できるか」を厳密に評価

---

## 【3】技術説明 ④: データリーク防止（こだわりポイント）

「投入前に成功確率を予測する」アプリである以上、
**実行後にしか分からない情報**（消費電力・実行時間・flopsなど）は
一切使ってはいけない

- 使った特徴量: ノード数・経過時間上限・メモリ上限・周波数・投入時刻/曜日
- 使わなかった特徴量: 実測の消費電力・flops・CPU時間 など（実行後の情報）
- 開発中に見つけた「使うとリークになりかねない/不安定な特徴量」も除外
  - ユーザーID → 匿名化IDが実際の利用者と対応せず実運用で意味がない
  - ジョブ実行環境 → ある時点を境に分布が恒久的に切り替わり、未来に汎化しない

---

## 【3】技術説明 ⑤: システム構成

```
ブラウザ（HTML/CSS/JS）
      ↓ フォーム送信
FastAPI（Python）
      ↓ 特徴量に変換
学習済みモデル（PyTorch）+ 確率較正器
      ↓
成功確率を返す
```

- バックエンド: FastAPI + PyTorch
- フロントエンド: 素のHTML/CSS/JS（フレームワークなし、シンプルなフォーム）
- 開発: Claude Code（AIコーディングエージェント）を活用
